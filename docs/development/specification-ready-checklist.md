# Specification-Ready Checklist

Apply `status:ready` only when every item is satisfied.

- [ ] Objective describes one observable result.
- [ ] Governing specifications and ADRs are linked.
- [ ] Blocking dependencies are merged.
- [ ] Required behavior is explicit.
- [ ] Expected files are listed.
- [ ] Public interfaces and data contracts are exact where applicable.
- [ ] Approved dependencies and prohibited shortcuts are stated.
- [ ] Non-goals prevent obvious scope expansion.
- [ ] Automated criteria cover success and relevant failure cases.
- [ ] Concurrency, ordering, idempotency, persistence, recovery, compatibility, security, and limits are addressed where applicable.
- [ ] Human Godot validation is actionable or explicitly not required.
- [ ] Evidence requirements are stated.
- [ ] Stop conditions prevent architectural improvisation.
- [ ] The issue is small enough for one pull request and one coherent review.
